# Hackathon Track 1 — Causal variant prioritization (single proband)

Reproducible code and documentation for our submission. Starting from paired-end WGS reads of one
proband, the pipeline performs read QC, alignment and germline variant calling (GATK Best Practices),
offline annotation with Ensembl VEP, and phenotype-driven prioritization (HPO) that produces the
ranked submission file.

All processing runs on local infrastructure: no proband data are sent to third-party services.

## Pipeline overview

| Step | Tool | Script | Output |
|---|---|---|---|
| 0. Raw read QC | FastQC (+ MultiQC) | `00_fastqc.sh` | QC reports on raw reads |
| 1. Trimming and filtering | fastp; FastQC on trimmed reads | `01_fastp.sh` | trimmed FASTQ, fastp HTML/JSON, QC reports |
| 2. Alignment | BWA-MEM + samtools sort | `02_fastq_to_vcf.sh` | coordinate-sorted BAM |
| 3. Duplicate marking | Picard MarkDuplicates | ″ | deduplicated BAM + metrics |
| 4. Read groups | Picard AddOrReplaceReadGroups | ″ | BAM with read groups (PL=MGI) |
| 5. BQSR | GATK BaseRecalibrator + ApplyBQSR | ″ | recalibrated BAM |
| 6. Variant calling | GATK HaplotypeCaller | ″ | single-sample VCF (GRCh38) |
| 7. Normalization and annotation | bcftools norm + Ensembl VEP 115 (offline) + ClinVar | `03_vep_annotate.sh` | annotated VCF, variant table, pre-filtered candidates |
| 8. Prioritization and submission | HPO phenotype match + variant evidence + inheritance | `04_prioritize.sh` / `04_prioritize.py` | ranked table and `submission/<user>_<approach>.csv` |
| 9. ClinVar P/LP in disease genes | ClinVar Pathogenic / Likely_pathogenic / Pathogenic/Likely_pathogenic (no conflicts) in genes with an HPO-annotated disease; no frequency filter; independent of the ranking | `05_clinvar_plp.sh` / `05_clinvar_plp.py` | `clinvar_plp/<ID>.clinvar_plp_disease_genes.tsv` |

`scripts/run_pipeline.sh` runs all steps in order and writes one log per step.

Reference genome: **GRCh38** — `GCA_000001405.15_GRCh38_no_alt_analysis_set`.
BQSR known sites: 1000G phase 1 high-confidence SNPs (hg38) and dbSNP 138 (hg38),
from the GATK resource bundle.

## Key parameters

**FastQC**: default parameters, on raw and on trimmed reads.

**fastp**
- `--correction` (overlap-based base correction for paired reads)
- `--cut_front 25 --cut_tail 25 --cut_mean_quality 25` (sliding-window trimming at both ends, mean Q ≥ 25)
- `--trim_front1 7 --trim_front2 7` (removes the first 7 bases of R1 and R2)
- `-l 70` (discards reads shorter than 70 bp)

**BWA-MEM**: default parameters. **HaplotypeCaller**: default parameters, single-sample VCF mode.

**bcftools norm**: `-m -any` (split multiallelic sites) and left-alignment against the reference.

**VEP** (offline Ensembl/GENCODE cache, GRCh38, release 115; full configuration in
[`docs/vep_configuration.md`](docs/vep_configuration.md)): `--symbol --transcript_version --hgvs --hgvsg
--canonical --mane --biotype --numbers --protein --uniprot --variant_class --check_existing --pubmed
--distance 5000 --af --af_1kg --af_gnomade --af_gnomadg --max_af --sift b --polyphen b --flag_pick`,
ClinVar (`CLNSIG`, `CLNREVSTAT`, `CLNDN`) as exact-match custom annotation, and the NMD and
AlphaMissense plugins (other plugins are enabled when their data files are configured). No frequency
or consequence filtering is applied inside VEP.

**Candidate pre-filter**: non-reference genotype; DP ≥ 10; GQ ≥ 20; gnomAD `MAX_AF` < 0.01 or absent;
and HIGH/MODERATE impact, splice-related consequence, or ClinVar pathogenic/likely pathogenic
(non-conflicting).

**Prioritization and EPCR** (`04_prioritize.py`):
`EPCR = variant_score × (0.3 + 0.7 × pheno_score) × inheritance`, where `variant_score` summarizes
ClinVar, predicted consequence, in silico predictors, gene constraint and population frequency;
`pheno_score` is the fraction of the proband's HPO terms annotated to the gene (including descendant
terms); and `inheritance` reflects consistency of the genotype with the gene's mode(s) of inheritance.
Two qualifying heterozygous variants in a recessive gene form one compound-heterozygous finding;
phase is not determined (single proband, no read-backed phasing), so pairs are reported as candidates.
Scoring weights are heuristic (ordered by ACMG/AMP evidence strength, not calibrated); their basis
and the limitations of this run are described in [`docs/prioritization.md`](docs/prioritization.md).

**Manual evaluation**: the candidate list generated by the prioritization (step 8) and the ClinVar
P/LP list (step 9) were evaluated manually to verify the congruence of the process; see
[`docs/prioritization.md`](docs/prioritization.md#manual-evaluation).

### Installation

| Environment | Packages | Steps |
|---|---|---|
| `qc` | fastqc, fastp | 0–1 |
| `align` | bwa, samtools, htslib | 2 |
| `gatk_vcf` | picard, gatk4, openjdk, samtools | 3–6 |
| `vep_env` | ensembl-vep, bcftools, htslib, python | 7–8 |

```bash
for e in qc align gatk_vcf vep; do conda env create -f envs/${e}.yml; done

# One-time setup: VEP cache (if absent), plugins, AlphaMissense, ClinVar and HPO
bash scripts/setup_vep_resources.sh config/config.sh
```

Reference indexes (once):

```bash
bwa index GCA_000001405.15_GRCh38_no_alt_analysis_set.fna
samtools faidx GCA_000001405.15_GRCh38_no_alt_analysis_set.fna
picard CreateSequenceDictionary R=GCA_000001405.15_GRCh38_no_alt_analysis_set.fna \
    O=GCA_000001405.15_GRCh38_no_alt_analysis_set.dict
tabix -p vcf 1000G_phase1.snps.high_confidence.hg38.vcf.gz
gatk IndexFeatureFile -I Homo_sapiens_assembly38.dbsnp138.vcf
```

### Hardware

Peak memory ~60 GB (GATK BaseRecalibrator). Threads: 40 (fastp), 35 (BWA-MEM), 16 (VEP), configurable.
Disk: ~25 GB for the VEP cache. Annotation of one genome (~5 million records) took ~2 h with 16 threads.

## Usage

```bash
git clone https://github.com/<user>/<repo>.git
cd <repo>

cp config/config.example.sh config/config.sh       # edit paths, SUBMISSION_USER, PROBAND_SEX
echo "<PROBAND_ID>" > samples/samples.txt
# samples/<PROBAND_ID>.hpo.txt: one HPO term per line (see samples/HKT.hpo.txt)

bash scripts/run_pipeline.sh config/config.sh       # all steps
bash scripts/run_pipeline.sh config/config.sh 3     # resume from script 03 (VEP)
```

Input naming: `<ID>*_1.fastq.gz` / `<ID>*_2.fastq.gz` in `FASTQ_DIR`.
